# Census тренувань і прогонів — що, скільки, як швидко, з яким результатом

Зведення по всій роботі над ботом (2026-07-11 … 2026-07-25). Заповнює дірку, якої не закривав
`experiment-log.md`: там 42 записи «config → результат» по окремих варіантах, але не було відповіді
на «**що саме ми натренували, скільки прогонів, яка швидкість, скільки ітерацій**».

**Джерела чисел** (не з пам'яті — з файлів): тренувальні логи `tmp/curriculum-train/logs/*.log` і
`tmp/retrain-prep/ntuple/run/ab/*.log`, `perf.json` у `project/research/experiments/*/`, чекпоінти в
`tmp/*/ckpt/`, самі записи `docs/experiment-log.md`. **`tmp/` у git не лежить** (2.9 GB, gitignored) —
тому числа нижче виписані сюди, поки логи ще існували.

## 1. Що це за модель

| | |
|---|---|
| Архітектура | **8×6-tuple** value network (n-tuple network), **14,172,488 вагів ≈ 57 MB** на чекпоінт |
| Навчання | afterstate **TD(0)**, Hogwild (lock-free паралельні воркери), `tc=true` (temporal-coherence learning rate) |
| Крок навчання | `alpha` = 0.100 … 0.150 |
| Воркери | 8 … 14 (14-ядерний M4 Pro) |
| Цільова функція чемпіона | **EXP (risk-seeking)**: `lambda=0.0030`, `base=1800`, `step=e^λ=1.003005`, `W(death)=0.00452` |
| Базова нагорода | SURVIVAL: **+1 за хід**, термінал 0 |
| Пошук у грі | expectimax, **depth 4** (продакшн), `cprob` cutoff, leaf = мережа |

`λ` — це risk-tilt: експоненційна корисність замість очікуваного числа ходів. λ=0.003 — **чемпіон**;
сусідні λ (0.001…0.020) натреновані й перевірені (`tmp/champion-backup-2026-07-11/weights/w-l*.bin`),
вищі λ дають більше ризику й НЕ доходять до щільної рекордної дошки (запис 2026-07-22, RED).

### Швидкість тренування — що з неї видно
- Пік **4,037 eps/s на 14 воркерах**; 1,984 eps/s на 8 і 1,453 eps/s на 12 — тобто **12 воркерів
  виявились ПОВІЛЬНІШЕ за 8**, коли на машині паралельно щось крутилось. Це та сама CPU-contention,
  через яку правило «один game-runner за раз» (див. `docs/knowledge/2048-simulation-discipline.md`).
- «fresh» < «episodes» завжди: backward curriculum перезапускає частину ігор із **planted** дошок,
  тому реальних нових ігор ~55% від епізодів (43.6M → 24.0M fresh).

### Curriculum (як саме тренували)
- **Backward curriculum**: `seedp` = 0.45 … 0.60 — з такою ймовірністю епізод стартує не з порожньої
  дошки, а з **planted** дошки з банку: **24,000** дошок (`phaseA_mix.txt`), phaseB — **5,996**.
- Банки сідів по глибині: `seeds_d0/d1/d2/d3_train.txt` — вирішує проблему visitation (мережа сама
  майже не доходить до щільних late-game дошок, тому їх підсовують).
- **Carousel** 0.00 … 0.20 — пул ендгейм-рестартів по k=1..4 (8192 дошки на рівень).
- Warm-start від чемпіона майже завжди — тренування «з нуля» (`scratch`) робили як контроль.

| Типовий eval-прогін `masshunt` | n ≈ 500 … 2,570 ігор на арм |

**Швидкість движка** (заміряна, `perf.json` + запис 2026-07-12):
- depth-6 farm, 13 воркерів: **28.9 ходів/с**, 422.6 мс/хід, **58.8 ігор/год** (це «важкий» режим).
- Perf-стек (leaf-cache 64MB + PGO + GOAMD64=v3 + workers 8) дав **2.24× на live-шляху**
  (7,837 → 3,501 мс), nodes/s 1.97e5 → **4.33e5**, hit-rate leaf-кешу **60.9%**.
  Чексум рішень `1c04de39f1130696` **не змінився** — ускорення bit-exact, ходи чемпіона ті самі.
- Live на телефоні: цільова каденція 5 свайпів/с; продакшн depth-4 у бюджет вкладається.

## 4. Які варіанти перевірили — де успіх, де ні

### ✅ Що зайшло і лишилось у продакшні
| варіант | що дав |
|---|---|
| **2048 stop-rule** підтверджено живцем | фундамент усього маршруту: гру можна зупинити на 2048 і забрати рахунок |
| **HEUR1/HEUR2** (snake + rank-corner + stair, ендгейм empty-convexity) | відкрили хвіст розподілу; 50k став питанням частоти, не можливості |
| **Чемпіон = tail-net λ=0.003** | зсунув увесь розподіл, а не лише максимум |
| **Cash-out +2048** (підтверджено live) | рекорди 49.6k / 49.4k |
| **Banking leak fix (earlyfire над mass-guard)** | **0/16 → 13/16** — рекордні дошки почали банкуватись БЕЗ ретрейну |
| **Target-conditioned солвер `-exact`** | замінив евристичне EV-правило на точний ендгейм-максимайзер |
| **Perf-стек** (leaf-cache/PGO/v3/w8) | 2.24×, bit-exact ⇒ +~1 rung горизонту за той самий бюджет |
| **Soft leaf-пенальті** (як принцип) | м'які штрафи допомагають; **жорсткі veto — шкодять** (доведено 3×) |

### ❌ Що перевірили і закрили
**Тренування / цільові функції (усі RED):** mass-ретрейн (нагорода merge-інваріантна → сходиться до
чемпіона) · wall + wallgate ретрейни (10.7M і 4.0M епізодів; maxN512@k4 = 1 у ОБОХ, як у чемпіона) ·
risk-seeking вищий λ · **expectile-TD** · support-carrier **β-sweep** (6×5M епізодів — чистий *squeeze*:
шейпінг або колапсує виживання, або стабільний і не хоардить; це ж убило й distributional-QR
follow-up) · curriculum-stacker · backward-curriculum R3-exec.

**Пошук / евристики (усі RED):** depth 5 (катастрофа) і depth 7 · `cprob=1e-5` (задорого) ·
soft leaf-shaping 1024-clustering+snake+512-taboo (стеля Φ≈48k тримається) · fill-adaptive
support-hoarding · **κ risk-tilt** на чемпіоні · **QD/MAP-Elites** по farm-леверах ·
**goal-beam планер** · planner-probe option C · **online CMDP** constrained-search.

**Ендгейм / банкір (усі RED):** doom-oracle тайминг · EV-fire (superseded `-exact`) · зниження
банкір-порогу під 48500 (мертва смуга — убиває топ-3) · support-conditional cash target ·
**max-P tablebase** (V=0 на всіх дошках, яких чемпіон реально досягає) · **endgame calibration**
(champion vs точний DP: розбіжність 34-36%, але форсування DP-ходу дає **нуль** зайвого виживання).

**Інше:** k=5 резервуарів — мертвий двічі (і під сильною політикою) · cooperative-spawn probe
(будується, але P\*≈4e-179 — потрібен людський обсяг) · MLP-eval gather-split (негативно на M4) ·
PoC-B human-imitation (не запускали — потребує живої гри людиною).

### 🧱 Головний висновок
**10 ортогональних доказів стелі** (R4 EV-gate, DP max-P tablebase, coop-probe, ретрейни
mean/mass/expectile, highvar-β шейпінг, farm-MAP-Elites, κ-tilt на чемпіоні, goal-beam планер,
CMDP constrained-search + 1 banker-optimal), плюс endgame-calibration як фінальний пре-чек
архітектури (2026-07-25) — кожен *інший* клас важеля впирається в ту саму **fill-pressure геометрію**.
Одноігрова стеля **≈ 51-52k** підтверджена двома незалежними метриками (емпірична рідкість хвоста
~1.2e-4 при n=8220 і аналіз досяжності 52,212). Рекорд конкурента 58k нашими важелями невідтворний.
Єдиний шлях далі — **throughput** (більше живих спроб виловити рідку дошку), а це операційне рішення,
не дослідницьке. Деталі й розбір кожного доказу: `docs/knowledge/beat-58k-via-k4-cascade.md`,
`docs/knowledge/beat-58k-final-closure.md`.
